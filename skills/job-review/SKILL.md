---
name: job-review
description: Independently review a prepared job application for evidence quality, exact answers, PDF rendering and ATS text recoverability before it can be transmitted.
---

Start in a fresh context distinct from the preparer. First receive raw job description, inspection, candidate source pointers and current decisions, without the preparer's draft, narrative or evidence map. Save your own ranked assessment and retrieval trail before opening the draft. If no independent worker/context can actually be arranged, mark review pending. Do not manufacture run IDs or self-review.

Check that the strongest specific match is visible and any omissions are deliberate; verify claims against detailed sources rather than the preparer's wording. Check role, employer, dates, ownership, quantities, terminology, disclosure constraints and evidence for each exact answer. Look for unsupported claims, unexplained gaps, wrong job/company, and mismatch with actual required fields or letter limits.

For every PDF, inspect the exact build receipt, both text views and every page image. Recover key contact, chronology and role-to-achievement relationships without using the source to mentally fill in missing context. Compare to the source, then inspect margins, layout, line wraps, clipping and breaks. Resolve each warning individually with concrete observations, or request revision. A local text pass does not establish what the employer’s parser sees.

Write findings and a `pass`, `revise`, or `needs_fact` outcome. A pass binds exact package, visual evidence and concrete findings per [the contract](../../docs/WORKFLOW.md). Recheck changes before signing a new revision. The CLI tests consistency and bytes; the execution owner must verify actual reviewer/session provenance and review quality. Do not upload, edit the package, change policy or update the tracker.
