---
name: job-apply
description: Inspect an employer application form and execute a reviewed application only when the candidate has authorized the exact actions and scope.
---

Read [the execution contract](../../docs/WORKFLOW.md) and [form and recovery guidance](../../docs/APPLY.md). Work on one canonical requisition, reconcile history and lock the private workspace for browser work. This does not lock unrelated tabs or tools.

Inspect the employer form read-only before preparing. Capture actual destination, requisition, field prompts and labels, document requirements, limits, consent wording, conditions, and visible ATS evidence. Mark partial coverage honestly; do not reveal fields through unauthorized data entry. Hold for a user handoff on login, CAPTCHA, unsupported automation, assessment or unclear authority.

When starting with only a posting, register and screen it with [intake and screening](../../docs/WORKFLOW.md#1-intake-and-screening). If a package is needed, hand off to separate fresh [preparer](../job-prepare/SKILL.md) and [reviewer](../job-review/SKILL.md) workers. An unavailable browser means inspection remains pending; user-supplied current form evidence can support local preparation. An unavailable independent reviewer means quality review remains pending.

Show the concrete role/destination, reviewed answers, attachments and hashes, relevant consent choices, gaps and the exact action scope before requesting per-package authority. Check authorization and exact review before transmitting any candidate data, then again before submission. A new field, destination, answer, consent, or file invalidates affected review/authorization. Follow observed upload controls, check attachment slot and filename, verify autofill values and compare live final fields to the reviewed set. Save the submit-started checkpoint before a single authorized final click; never treat the checkpoint as proof of external action.

Use [job-track](../job-track/SKILL.md) to verify and record the result. On ambiguity, stop and reconcile read-only. Persist concrete exceptions and release only your own lease on clean exit. No external messaging, account changes, optional consent, or third-party test uploads.
