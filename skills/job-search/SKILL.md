---
name: job-search
description: Coordinate a job-search run from sourcing or supplied postings through screening and application preparation, and authorized application and tracking when in scope.
---

Resolve the toolkit checkout and private workspace using [the operating contract](../../docs/WORKFLOW.md). If needed, use [onboarding](../job-search-onboard/SKILL.md). This skill can start at any stage with the artifacts required by that stage. A standalone discovery, screening, preparation or review request ends at its requested stage.

1. Read the ledger and recover unresolved attempts before new submissions. Coordinate one browser owner per private workspace. Never retry an uncertain application on a new alias.
2. Use [job-discover](../job-discover/SKILL.md) and [job-screen](../job-screen/SKILL.md). Hand off the raw posting, stable role ID, score, hard gaps and unknowns. Rank eligible roles and note user-priority roles separately from objective scores.
3. Use [job-apply](../job-apply/SKILL.md) for read-only form inspection. For each selected role, give a fresh preparer [job-prepare](../job-prepare/SKILL.md), the job, observed form, sources and bounded output path. After preparation, assign a different fresh reviewer [job-review](../job-review/SKILL.md). Workers have no browser or execution authority.
4. Continue from the reviewed package according to the user's request and policy. Default to a reviewable local package. Submission requires actual authority, current exact package checks and a durable attempt before the browser click. Use [job-track](../job-track/SKILL.md) for confirmation and interrupted work.

Report discovery coverage, screening decisions, prepared/held roles, any data transmitted, verified receipts and unresolved attempts separately. Give concrete next actions and local evidence links. A partial source or one blocked application need not block independent preparation. Do not infer timing, worker models, browser identity, or authorization from examples.
